Server Rack

  • Portal และ Chat Hub
  • Console pages: Observability, Usage & limits, API keys, Playground
  • Responsive layout
  • Dark theme ด้วย CSS variables
  • ปุ่มและ panel ใช้ aria-expanded และ hidden ให้ตัวอ่านหน้าจออ่านสถานะได้
  • ทดสอบบนความกว้างมือถือก่อนเดสก์ท็อป ไม่มีการเลื่อนแนวนอน

  • server.py บน Python http.server (stdlib only)
  • Session login แบ่งบทบาท USER, ADMIN และ CEO
  • Rate limit
  • RAM-pause guard ตอบ 503 เมื่อหน่วยความจำเต็ม
  • Ollama model backend รันบน CPU
  • ตรวจ Origin ของคำขอที่เปลี่ยนสถานะ (POST, PUT, DELETE) ก่อนรับงาน
  • แยก route สาธารณะกับ route ที่ต้อง login ชัดเจน และตอบ 401 เมื่อไม่มี session

  • Per-user usage store และ conversation store
  • ผู้ใช้อื่นเข้าแชทของคนอื่นจะได้ 403 หรือ 404 และไม่มีเนื้อหารั่วไหล
  • Config files เขียนแบบ atomic
  • สำรองไฟล์ข้อมูลก่อนย้ายโครงสร้าง (migration) ทุกครั้ง
  • ข้อมูลส่วนตัวของผู้ใช้เก็บแยกตาม user id และไม่ส่งออกนอกเครื่องโดยไม่ได้รับอนุญาต

  • OpenAI-compatible: /v1/chat/completions และ /v1/models
  • Bearer auth
  • Error envelope {error:{message,type,param,code}}
  • Streaming ผ่าน SSE จบด้วย [DONE]
  • Rate-limit headers
  • รุ่นของ API ระบุใน path หรือ header และแจ้งล่วงหน้าก่อนเลิกใช้
  • ตัวอย่างคำขอและการตอบกลับอยู่ในเอกสาร และตรวจด้วย test ได้

  • LCA server พอร์ต 8420 (default)
  • Ollama พอร์ต 11434
  • Optional forwarding ระหว่างสองโหนดในระบบ LAN
  • แต่ละ service มีจุดเริ่มและหยุดที่บันทึกไว้ และไม่ทิ้ง process ค้างหลังปิดเครื่อง
  • เปิดเฉพาะพอร์ตที่ต้องใช้ และจำกัดวง LAN ด้วย firewall

  • Admin monitor ผูกกับ 127.0.0.1:8425
  • สถานะ usage: ok, partial, error
  • หน้า Observability
  • Quota ต่อ key
  • บันทึก log โดยไม่มี secret หรือ token อยู่ในข้อความ
  • แจ้งเตือนเมื่อ error rate หรือ RAM เกินค่าที่ตั้งไว้

Lifecycle: Plan, Design, Structure, Scale

1

Plan

กำหนดขอบเขต เป้าหมาย และเงื่อนไขว่าเสร็จเมื่อไหร่ ทุกขั้นมี acceptance ที่ตรวจได้

2

Design

กำหนดสัญญาระหว่างส่วน (API, ข้อมูล, สิทธิ์) ก่อนเขียนโค้ด และบันทึกเหตุผลของการตัดสินใจ

3

Structure

แยกโมดูลตามหน้าที่ หนึ่งไฟล์มีผู้เขียนเดียวในแต่ละรอบ และใช้ขนาดฟังก์ชันที่อ่านได้

4

Scale

เพิ่มกำลังทีละขั้นตามตัวเลขที่วัดได้ เช่น RAM, latency และโควตา ไม่เพิ่มล่วงหน้าโดยไม่มีข้อมูล

Knowledge pillars

Arch

Architecture

ดูภาพรวมที่ docs/ARCHITECTURE.md และบันทึกการเปลี่ยนแปลงสำคัญเป็น decision record

Docs

Documentation

ทุกฟีเจอร์มีเอกสารสั้นใน docs/ ที่บอกว่าทำอะไร ไม่ทำอะไร และวิธีรัน

Test

Testing

แผนทดสอบอยู่ที่ docs/TEST_PLAN.md และ docs/QA_CHECKLIST.md ทุกการแก้ไขต้องมี test ที่ fail ก่อนและ pass หลังแก้

Ship

Deployment

ขั้นตอนอยู่ที่ docs/SETUP.md เริ่มจากวง LAN เท่านั้น ยังไม่เปิดสาธารณะ จนกว่าจะมีการอนุมัติ

ตัวอย่างจาก REA: วิเคราะห์ Claude desktop app (ไม่ใช่ LCA)

การวิเคราะห์แบบ static เท่านั้น ไม่ได้รันแอป ไม่ได้คัดลอกโค้ด และไม่ได้ดึง key หรือ token เวอร์ชัน 5.11492.5.0 วันที่ 19 พ.ย. 2026
