# หลักคิด 9arm ที่ใช้จริงในโปรเจกต์ LCA

> "สมอง" ของโปรเจกต์นี้ — หลักคิดแบบ 9arm (ธนานนท์ ปฏิญญาศักดิกุล) ที่ใช้ตัดสินใจทุกก้าว
> *หมายเหตุ:* ไฟล์นี้คือความรู้ 9arm ที่เก็บไว้ **ในโปรเจกต์ 9nammon** (ไม่ใช่การแก้ plugin skill
> ตัวจริง ซึ่งอยู่นอก repo นี้) — ใช้เป็น reference เวลาพัฒนา LCA ต่อ

---

## 1. วัดก่อนตัดสิน — อย่าเดา (measure, don't guess)

หัวใจที่สุด ทุกการตัดสินใจเรื่องฮาร์ดแวร์/โมเดลในโปรเจกต์นี้มาจาก **ตัวเลขจริง** ไม่ใช่ความรู้สึก
- "GPU ต้องเร็วกว่า CPU" → **วัดแล้วผิด** บนเครื่องนี้ (CPU ชนะ iGPU 18%)
- "0.5b น่าจะพอ" → **วัดแล้วไม่พอ** สำหรับแก้โค้ด (10/11); 1.5b ถึงจะ 100%
- **อุปมา:** จะซื้อรถเพิ่มแรงม้า ต้องรู้ก่อนว่าติดตรงเครื่องหรือตรงยาง — ไม่ใช่เหมาเปลี่ยนทั้งคัน

## 2. ซ่อมไม้บรรทัดก่อนวัด (fix the ruler first)

เจอ eval ให้ผล 10/11 แล้ว 8/11 (โค้ดเดิม) → **ไม่รีบสรุป** แต่รู้ว่า "เครื่องมือวัดมันสั่น"
→ แก้ให้ deterministic (temp=0) ก่อน แล้วค่อยวัดต่อ
- **บทเรียน:** ข้อมูลที่ noisy แย่กว่าไม่มีข้อมูล เพราะมันหลอกให้ตัดสินใจผิดด้วยความมั่นใจ

## 3. ดูของจริงก่อนแก้ (look at the actual output)

เคส edit ตก → **ไม่เดา**ว่าเพราะ format เพี้ยน แต่ไปดู raw output จริง: โมเดลตอบ `` ```x = 2``` ``
ไม่มี SEARCH block → รู้ทันทีว่า "ข้อมูลไม่ครบ" ไม่ใช่ "format ผิด"
- **ผลลัพธ์:** เลี่ยงทางแก้ที่อันตราย (ทำ parser ให้หลวม → อาจพังไฟล์) ได้ เพราะเห็นสาเหตุจริง

## 4. Intellectual honesty — ไม่ขายฝัน

บอกตรงทุกครั้งว่าอะไร **ทำไม่ได้**บนเครื่องนี้ แม้ user อยากได้:
- netbook รองรับ 1,000 คนพร้อมกันไม่ได้ (รับจริง 1–2)
- vLLM/เทรน บน 8GB+iGPU ทำไม่ได้ → ต้อง cloud
- cloud session (ตัว agent) โฮสต์แทน user ไม่ได้
- **ทำไมสำคัญ:** ความจริงที่ไม่อยากได้ยิน > คำชมที่พาไปเสียเงิน/เสียเวลาเปล่า

## 5. เชื่อมทฤษฎีกับการใช้งานจริงเสมอ

ไม่พูดลอยๆ — ทุกข้อสรุปผูกกับตัวเลขที่ใช้ตัดสินใจได้:
- "เน็ตไม่ใช่คอขวด" → gen 200 token ~12 วิ แต่ส่งเน็ตแค่ ~1–5KB
- "RAM คือคอขวด" → พิสูจน์ 2 ด้าน (ความเร็ว + คุณภาพ) ชี้จุดเดียวกัน

## 6. ใช้อุปมาจากชีวิตจริง

อธิบายของยากด้วยของใกล้ตัว:
- iGPU แชร์ RAM bus กับ CPU = **"สองคนดูดน้ำจากหลอดเดียวกัน"** ไม่เร็วขึ้น
- โมเดลเล็กทำตามกฎไม่ได้แต่เลียนแบบตัวอย่างได้ = **"เด็กเล็กดูตัวอย่างทำตามง่ายกว่าอ่านคู่มือ"**

## 7. ทำทีละขั้น ตัดสินด้วยข้อมูล ขยายตามจริง

ไม่กระโดด: เริ่มเล็ก (0.5b/เครื่องเดียว) → พิสูจน์ → ค่อยขยาย (1.5b/VPS/cloud) ตามรายได้+ข้อมูลจริง
ไม่ลงทุนล่วงหน้ากับสิ่งที่ยังไม่มีข้อมูลยืนยันว่าจำเป็น
